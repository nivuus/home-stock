# pytest-homeassistant is the harness published from home-assistant/core, one
# release per Home Assistant release. It replaces
# pytest-homeassistant-custom-component, whose README declares it broken since
# that move and whose last release (0.13.375, 2026-10-25) pins Home Assistant
# 2026.10.4 and through it Pillow 12.3.0, which pip-audit flags. Do not install
# both: they register overlapping fixtures (pytest-homeassistant README).
#
# THE TEN BELOW ARE NOT TEST TOOLS, and none of them is a dependency this
# repository chose. The harness installs Home
# Assistant WITHOUT any per-integration requirement (those normally arrive at
# setup time, per component, in a real install), so every component this suite
# reaches must have its own requirements listed here by hand or it fails to
# import - as a collection error, a setup failure, or a test failure, depending
# on where it is reached from.
#
# Nothing had ever noticed: `python / Python checks` failed at the ruff step on
# every run since 2026-08-27, so pytest was NEVER reached in CI and this whole
# suite has never run there. Bringing ruff to green surfaced it in one go:
# 471 failed, 53 errors, then 22, then 21, one missing module at a time.
#
# WHERE THEY COME FROM, and why the list is closed rather than guessed:
#
#   1. manifest.json declares dependencies http, websocket_api, panel_custom.
#      panel_custom needs frontend, and frontend imports hass_frontend at
#      setup: without home-assistant-frontend, frontend fails, panel_custom
#      fails with it and home_stock never sets up.
#   2. custom_components/home_stock/receipt/task.py imports
#      homeassistant.components.ai_task, which reaches, at module level:
#      ai_task -> entity -> task -> camera, conversation, image, media_source.
#      Note that ai_task/task.py imports camera and image WITHOUT declaring
#      them in its own manifest.
#   3. async_get_all_descriptions() - which tests/test_services.py and
#      tests/test_surface_parity.py call - goes through
#      homeassistant.helpers.service._base_components(), and that function
#      imports NINETEEN components unconditionally, assist_satellite and
#      media_player among them. That is where tts, ffmpeg and the voice
#      libraries come in, for an integration that has nothing to do with any
#      of them.
#
# The list is the transitive closure of the manifests of those three roots in
# Home Assistant 2026.11.1 - the release the pin above resolves to. Bumping
# pytest-homeassistant moves that release, and these with it: recompute the
# closure against the new one rather than editing a line. Dependabot is told
# to leave these ten alone for that reason (.github/dependabot.yml).
#
# How it is computed: walk module-level imports (outside functions and
# TYPE_CHECKING) from the three roots, plus the manifest "dependencies" of
# every component that is SET UP, and collect the manifest "requirements" of
# every component reached that the pin does not already install. One entry of
# that walk is deliberately absent: av, required by stream. camera imports
# stream at module level, but stream is never set up here and imports av only
# inside functions, so nothing ever executes `import av`. Run against 2026.8.2,
# the same walk gives back exactly the previous list; against 2026.10.2 it adds
# gazetteer-matcher, which conversation now requires and imports at module
# level in default_agent.py.
#
# Recomputed for 2026.11.1 with the same walk, which first gave back exactly
# the 2026.10.4 manifests' versions when run against that release (main had
# drifted from them through one-line Dependabot bumps). 2026.11.1 adds numpy:
# stream now imports it at module level, and the old harness used to install
# it as its own dependency, which pytest-homeassistant does not.
gazetteer-matcher==1.1.0
ha-ffmpeg==3.2.2
hassil==3.12.1
home-assistant-frontend==20261028.5
home-assistant-intents==2026.10.27
mutagen==1.48.1
numpy==2.3.2
